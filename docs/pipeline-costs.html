What it costs to turn 32 protocols into a consult sheet

Every figure on this page was measured on our corpus (32 PDFs, 4,142 pages) or read from Google's price list. The headline: building a protocol version costs a few euros with the strongest model, once; a lookup in the consult sheet costs nothing; the only running cost is keeping a server warm.

A consult-sheet lookup reads a prebuilt spec: no model call, no token cost. The model is paid only when a protocol version is uploaded and when someone opens the assistant. No patient data is stored anywhere: the assistant receives the question and the place in the protocol the clinician is looking at, logs token counts only, and keeps nothing. That removes a database of health data, its encryption, its access logs and its GDPR processing record from the bill.

Who writes each field

Every field description in spec.ts starts with who fills it. The model may only pick from enums and from ids that code already found. It never writes text a clinician reads.

The verification rule

A quote counts as found on a page only when both checks pass:

  1. A contiguous passage of the page text matches the quote with a similarity of at least 0.90, after normalising bullets, hyphenation, quote marks and the many spellings of ×10⁹/L.
  2. Every number in the quote appears in that passage with the same value, and no number is missing or extra.

The second check is what stops "WBC >3.0" from passing against "WBC >1.5": the words match, the numbers do not. A quote that fails is dropped, the edge is drawn as inferred, and a warning goes to the admin screen.

When a new version arrives

Upload builds a draft spec, the admin sees a diff against the published version (sections added, removed, changed text), and only then publishes. Hospital rules attached to a section that changed are flagged for reconfirmation, never carried over silently. Each version costs one labelling call, the $0.014 above.
